# Demand probe

The build is capped at two weeks. v0's engineering gate is that the three
mutations produce their documented severities, unchanged/equivalent fixtures
pass, and the installation + README examples run end to end.

Launch the public GitHub repository first and use it in direct engineering/sales
outreach, then Hacker News; Product Hunt can follow. The README must let a new user
clone, install, compare the fixtures and interpret the output without assistance.
The hosted CI must pass for the revision being shared. Publish the worked example
alongside the release. Only this standalone repository is in scope; Project-X's
private assets are excluded. Verify package-name availability before a separate
PyPI release; installation from the repository supports the GitHub-first launch.

Preserve the brief's additional publication gate: establish whether the historical
68.7 mm discrepancy comes from conversion/configuration drift or engine physics,
and retain the controlled attribution evidence. The synthetic demo and the model
comparisons in the beta validation record do not establish that causal result.
Choose the launch headline only after that evidence has been reviewed.

The distribution owner should put the command in front of engineers currently
converting robot models, help with initial setup, and continue discovery calls.
Agree on the audience and outreach effort before starting the observation window.
Review results a few weeks after distribution, not simply a few weeks after a
repository was created. A quiet release with little qualified exposure is
inconclusive about demand.

Manually record three signals only:

| Date | Team/contact | Signal | Evidence / useful finding / blocker |
| --- | --- | --- | --- |
| | | run-on-own-model / issue-filed / conversation-started | |

Record unsuccessful own-model attempts as such, including the blocker. Keep
contact details in a private copy of this log. There is no background collection,
mandatory upload, analytics endpoint or telemetry in the package.

Repeat usage, reduced reproductions, actionable issues and conversations about
real workflows support continuing the experiment. Downloads/stars alone do not.
No adoption after meaningful distribution is a reason to stop or revise the
probe; it is not proof that no team has the underlying problem. Utility of this
free tool also does not establish willingness to pay for a separate offering.
